secondary · how it is built

Responsibilities before component names.

Flotilla owns coordination and durable delivery. Supporting technologies keep narrow boundaries and do not become the product hierarchy.

The runtime boundary

Flotilla core

Bundled and required

The Go binary owns agent identities, routing, delivery records, lifecycle commands, observed session state, goals, and the local dashboard.

tmux

External and required for delivery

Flotilla identifies and drives running coding-agent panes through tmux. It does not replace the coding agent inside each pane.

Coding-agent runtimes

External and user supplied

Claude Code, Codex, Grok, OpenCode, Pi, and aider remain their own products and subscriptions. Flotilla coordinates them.

Discord

External and optional

Discord can provide an audit mirror and inbound chat surface. Local delivery, the clock, status, and the dashboard do not require it.

Memory and continuity boundary

Memex

External and optional

Memex is a separate memory system. Flotilla can write a bare pointer into a cross-runtime handoff for a future consumer, but it does not embed retrieved memory and Memex is not required for Flotilla to deliver work, preserve the handoff, or complete a runtime switch.
