02 · get running

From clone to a verified fleet.

This path starts with prerequisites, installs the exact public binary, defines two agent sessions, and checks what flotilla can see before you send work.

Before the first command

  • Git.
  • Go 1.26 or newer.
  • tmux.
  • At least one supported coding agent already installed and authenticated.

Discord is optional. Local coordination, status, and delivery work without it.

1. Install

git clone https://github.com/jim80net/flotilla.git cd flotilla go install ./cmd/flotilla flotilla version

If the shell cannot find flotilla, add $(go env GOPATH)/bin to your PATH.

2. Define the fleet

Create flotilla.json in the repository root:

{ "agents": [ { "name": "infra" }, { "name": "research" } ] }

The names are public examples. Each name becomes the stable identifier for one coding-agent session.

3. Verify before delivery

flotilla status --roster ./flotilla.json

Before the detector has observed a session, unknown is the honest state. The command reads the current snapshot; it does not invent liveness.

4. Connect a coding agent

This example uses Claude Code. Replace claude with another supported agent command when needed.

tmux new-session -d -s flotilla-demo tmux send-keys -t flotilla-demo 'flotilla register infra && exec claude' Enter

register gives the pane a stable identity even when the coding agent changes its title.

5. Send the first instruction

flotilla send --from me --roster ./flotilla.json infra "Report the repository status."

A successful send confirms that the agent turn started. A busy target is queued durably for later delivery; a missing or crashed target returns a typed refusal instead of a false success.

For the clock, Discord mirror, recovery recipes, and production operation, continue to the complete repository quickstart.
